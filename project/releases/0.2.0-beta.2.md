## Summary

Opt-in debug logging (`%APPDATA%\MyVNC\myvnc.log`, off by default) and a resource watchdog that
warns and always logs if the app looks like it is running away with memory/CPU — a direct
response to the runaway-memory incident found and fixed during the previous development cycle.
Also README improvements: installer link, session screenshots, a clearer Right Ctrl gesture, and
an updated GitHub "About" description.

## Regression testing done for this release

- `dotnet build` (Debug + Release) and `dotnet test tests/MyVNC.Rfb.Tests` (42 tests) green.
- **Live-verified**: enabled debug logging via UI automation, connected to a real host
  (<hostname>), and confirmed that the log captures server version/security type/VeNCrypt
  subtype/resolution without any user credentials. Confirmed that the "Open log" button is
  correctly enabled when the log file exists and opens it in Notepad.
- **Not tested** (code review only): the `ResourceWatchdog`'s actual warning path (no artificial
  memory/CPU load was forced to confirm that the MessageBox actually shows and `WriteAlways`
  logs), turning the logging switch off again and confirming that logging actually stops, the
  log file's 5 MB trimming, and the three unhandled-exception hooks
  (`DispatcherUnhandledException`/`AppDomain.UnhandledException`/`TaskScheduler.UnobservedTaskException`)
  — no real exception has been thrown to confirm that they actually catch and log.

## Risks

- See the untested paths above — the exception hooks and the watchdog warning in particular
  should be verified before relying on them in a real crash scenario.
