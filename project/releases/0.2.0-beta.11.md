# 0.2.0-beta.11

**Date:** 2026-08-16

## Summary

Live incident: the app felt hung and the computer became sluggish. The log showed every reconnect
event in **pairs**, in perfect lockstep — the same connection was dropped and reconnected twice
simultaneously. Root cause: the duplicate guard only compared the exact address string used for
the current connection attempt. The same physical machine reached via two different addresses
(e.g. LAN IP versus Tailscale IP for the same saved profile) therefore slipped past the guard and
got two simultaneous sessions open — doubling every reconnect/decode/render cost, driving memory
up continuously, and making the app sluggish enough to feel hung.

Fixed by comparing against **all** known addresses for a profile (Host IP, FQDN, Tailscale IP,
Tailscale FQDN), not just the one used for the specific connection attempt.

Also added a visible indicator: the Connect button (and the address-picker arrow) is now disabled,
with an explanatory tooltip, for every profile that already has a session open — so a duplicate
connection is visibly prevented up front instead of only being caught (and silently redirected)
after the click. The card itself can still be clicked and switches to the existing session.
