# 0.2.0-beta.1

**Date:** 2026-08-15
**Commit range:** `3dc4dc2..v0.2.0-beta.1` (release commit included).

**Included commits** (in git order, `3dc4dc2` excluded):
1. `chore: ignore local secrets and installer build artifacts`
2. `fix: enforce single-instance and fix runaway named-pipe retry loop`
3. `fix: session chrome no longer covers or clicks-through onto the remote desktop`
4. `feat: add SSH terminal shortcut and in-app Help overlay`
5. `test: add MyVNC.Rfb regression suite`
6. `docs: add README with screenshot and Hyprland limitations`
7. `build: add Windows installer and process-level smoke test`
8. `release: bump version to 0.2.0-beta.1` (this commit)

## Summary

The first beta since 0.1.0: enforced single-instance mode (with a runaway-memory bug found and
fixed during regression testing), a per-connection SSH terminal shortcut, a built-in help
section, a proper Windows installer, and a new regression test suite (unit tests for the RFB
library plus a scripted smoke test against the built Release executable).

## Why beta

This is an informal share with a few friends/colleagues (see [installer/](../../tooling/installer/)),
not a broad release — the beta tag signals that it has not been as thoroughly exercised across
production/many different environments as a `1.0.0` would be, even though the regression suite
(see below) passed cleanly.

## Changes

See [CHANGELOG.md](../../CHANGELOG.md#020-beta1---2026-08-15) for the full list.

## Upgrading

No data migration is required from 0.1.0 — the `connections.json`/`settings.json` formats are
unchanged. Install via `installer/MyVNC-Setup-0.2.0-beta.1.exe` (built with
`installer/build-installer.ps1`) or build and run the Release executable directly.

## Regression testing done for this release

- **Unit tests** (`tests/MyVNC.Rfb.Tests`, 42 tests): all ZRLE subencodings (Raw, Solid, Packed
  Palette, Plain RLE, Palette RLE), tile-grid boundaries, a continuous zlib stream across
  multiple rectangles, VNC-Auth DES key derivation, big-endian wire helpers, and Unicode→keysym
  mapping (including å/ä/ö, which previously caused a separate, environment-related problem).
  Two test failures were found initially — both in the tests' own expected values (a miscounted
  hex constant, and a password pair that happened to share the same 8-character prefix that DES
  actually uses), not in the production code.
- **Scripted smoke test** (`scripts/smoke-test.ps1`) against the built Release executable: the
  process starts, the main window appears and responds, a second instance is forwarded
  correctly (not a separate process), no memory leak over 5 s idle, clean shutdown. This exact
  test would have caught the runaway-memory bug (multiple GB within seconds) that was actually
  found and fixed during this development cycle.
- **Manual live verification** against real omarchy hosts throughout development (see the
  CHANGELOG for specific findings: a hit-testing bug in the session window's tab bar, a
  wlr-virtual-pointer limitation for panel flyouts, and more).

## Risks

- No broad multi-machine verification of the installer yet (tested locally with a silent
  per-user install, see `installer/build-installer.ps1`).
- The SSH terminal feature is new and only tested against Windows Terminal/PowerShell on one
  machine.
