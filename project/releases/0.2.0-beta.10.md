# 0.2.0-beta.10

**Date:** 2026-08-16

## Summary

Two separate fixes in this release.

**1. DesktopSize update bug.** Another home-grown RFB client (in a parallel session) showed a grey
screen after wayvnc switched output (DP-2 ↔ HEADLESS-VNC) — suspected cause: the client does not
handle the DesktopSize/ExtendedDesktopSize pseudo-encoding correctly and never requests a full new
frame after a resize. Checked the same thing in MyVNC.Rfb as a precaution, and actually found
exactly that bug: `HandleFramebufferUpdateAsync` always requested the next update as
`incremental`, even directly after a DesktopSize rectangle. `HandleDesktopResize` correctly
reallocates the local framebuffer to the new size, but an incremental request only asks the
server for what has changed from *its* point of view — it does not know that the client's buffer
is now empty, so parts of the newly resized framebuffer could remain unpainted. A full
(non-incremental) update is now requested whenever a resize rectangle was seen in the round.

**2. The session window's canvas background.** The root of `RemoteFramebufferControl` had
`Background="Black"` since the project's very first commit, which always completely covered the
session window's decorative canvas background — both in the letterbox margins around a connected
session (fit-to-window mode with a different aspect ratio) and before a session had even
connected. Changed to permanently transparent so the background shows through in both cases.

## Regression testing done for this release

- `dotnet build` (Debug + Release) green.
- All 42 unit tests in `MyVNC.Rfb.Tests` green.
- The DesktopSize fix is code-reviewed and the test suite is green, but it is not live-verified
  against an actual server-side resize (hard to reproduce in a controlled way from the MyVNC
  side) — `RfbClient` also has no protocol-level integration tests yet, only subcomponents such as
  `ZrleDecoder`.
- The canvas background change is live-verified.

## Risks

The DesktopSize fix should be considered a well-founded, targeted correction rather than a
conclusively confirmed fix until it has been seen working against a real resize.
