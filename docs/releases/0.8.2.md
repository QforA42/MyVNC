# 0.8.2

**Date:** 2026-08-18
**Commit range:** `v0.8.1..v0.8.2` (release commit included)

**Included commits** (in git order, `v0.8.1` excluded):
1. `fix: hide the reconnect overlay's Close button during an active auto-reconnect retry`
2. `release: bump version to 0.8.2` (this commit)

## Summary

A single UI bug fix, debugged live against a reported incident: clicking the Wake button against
<hostname> dropped the connection, and the session window closed shortly afterward — even though
the app's auto-reconnect (2 s backoff) was already on its way to reconnecting by itself.

The root cause was found in `myvnc.log`: at every incident `Scheduling reconnect ... in 2s` was
logged, but never the matching `Reconnected ... after N attempt(s)` — instead a new, manual
`Opening session` line showed up a few seconds later. That revealed that the tab was closed before
the already ongoing reconnect had a chance to complete. The UI showed a full-screen overlay with a
large, centered "Close" button already during the reconnect countdown itself (not just after the
app had given up), which made it easy to click away, by mistake or impatience, a session that
would otherwise have recovered on its own.

The fix hides the "Close" button while a reconnect attempt is in progress — the status text
("Reconnecting in Xs...") is still shown, but without the tempting button. The button is still
shown when auto-reconnect is turned off in Settings, or (indirectly, since the tab already closes
automatically) after all 3 attempts have given up.

## Regression testing done for this release

- `dotnet build` (Release) green.
- **Not live-verified**: the fix addresses a confirmed code path (verified via log analysis and

  not been retested live since the fix landed.

## Risks

- Low — the change is a single boolean flag (`tab.IsCloseVisible = false` instead of `true`)
  during the retry countdown. The tab header's own close button (in tab mode) and the window's
  regular title bar are not affected.
