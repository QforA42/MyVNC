# 0.2.0-beta.11

**Datum:** 2026-08-16

## Sammanfattning

Liveincident: appen kändes hängd och datorn blev seg. Loggen visade varje återanslutningshändelse
i **par**, i perfekt lås — samma anslutning tappades och återanslöts två gånger samtidigt.
Grundorsak: dubblettskyddet jämförde bara den exakta adress-strängen som användes för det aktuella
anslutningsförsöket. Samma fysiska maskin nådd via två olika adresser (t.ex. LAN-IP kontra
Tailscale-IP för samma sparade profil) klarade sig därför förbi skyddet och fick två samtidiga
sessioner öppna — vilket dubblade varje återanslutnings-/avkodnings-/renderingskostnad, drev upp
minnet kontinuerligt och gjorde appen tillräckligt seg för att kännas hängd.

Åtgärdat genom att jämföra mot **alla** kända adresser för en profil (Host-IP, FQDN, Tailscale-IP,
Tailscale-FQDN), inte bara den som används för det specifika anslutningsförsöket.

Lade också till en synlig indikator: Anslut-knappen (och adressväljar-pilen) inaktiveras nu, med
en förklarande tooltip, för varje profil som redan har en session öppen — så en dubblettanslutning
förhindras synligt i förväg istället för att bara fångas (och tyst omdirigeras) efter klick.
Själva kortet går fortfarande att klicka på och växlar till den befintliga sessionen.
