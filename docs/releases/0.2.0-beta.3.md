# 0.2.0-beta.3

**Datum:** 2026-08-15
**Commit range:** `v0.2.0-beta.2..HEAD` (release-commit inkluderad — se
`git log v0.2.0-beta.2..HEAD` för exakta hashar när taggen `v0.2.0-beta.3` sätts).

**Included commits** (i git-ordning, `v0.2.0-beta.2` exkluderad):
1. `docs: point README installer link at v0.2.0-beta.2`
2. `fix: throttle outgoing pointer-move events to ~60Hz`
3. `feat: block duplicate connections to the same host:port`
4. `fix: eliminate per-byte allocation in ZrleDecoder`
5. `release: bump version to 0.2.0-beta.3` (denna commit)

## Sammanfattning

Spårade och fixade en riktig, live-reproducerad resursincident: `ResourceWatchdog` (ny i
beta.2) fångade sustained 70-145% CPU av en kärna under en riktig session. Grundorsaken var en
otyglad `SendPointerEvent` per WPF-musrörelse (kan avfyras 100+ ggr/sek), som i värsta fall
bildar en feedbackloop med fjärrkompositorns egen markörritning. Åtgärdat med throttling till
~60Hz. En sekundär bidragande orsak — en heap-allokering per byte/pixel i ZRLE-avkodaren — är
också fixad. Dessutom: MyVNC tillåter nu bara en anslutning per host:port åt gången.

## Regressionstestning som gjordes inför denna release

- `dotnet build` (Debug + Release) och `dotnet test tests/MyVNC.Rfb.Tests` (42 tester, inklusive
  full ZRLE-täckning) gröna efter varje ändring, inklusive ZRLE-allokeringsfixen.
- **Liveverifierat**: reproducerade den faktiska incidenten (RESOURCE WARNING i myvnc.log vid
  66-145% CPU), mätte uppdateringstakten direkt mot den påverkade hosten (10-16
  uppdateringar/sek kontinuerligt) med en rå RFB-sond, implementerade throttlingen, och
  bekräftade via `Get-Process`-trådsampling att total CPU-belastning sjönk efter fixen (mätt
  under samma live-session, inte bara i teorin).
- **Inte helt verifierat**: exakt hur mycket ZRLE-allokeringsfixen ensam bidrog jämfört med
  pekar-throttlingen — de landade i samma release och testades tillsammans, inte isolerat mot
  varandra.

## Risker

- Duplicate-connection-vakten är ny och bara testad manuellt mot ett fåtal scenarier (samma
  host, olika host, flikläge). Inte testad mot fönsterläge (egna fönster per session) eller
  race conditions vid mycket snabbt upprepade anslutningsförsök.
