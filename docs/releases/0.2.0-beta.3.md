# 0.2.0-beta.3

**Date:** 2026-08-15
**Commit range:** `v0.2.0-beta.2..HEAD` (release commit included; this version was never
tagged).

**Included commits** (in git order, `v0.2.0-beta.2` excluded):
1. `docs: point README installer link at v0.2.0-beta.2`
2. `fix: throttle outgoing pointer-move events to ~60Hz`
3. `feat: block duplicate connections to the same host:port`
4. `fix: eliminate per-byte allocation in ZrleDecoder`
5. `release: bump version to 0.2.0-beta.3` (this commit)

## Summary

Tracked down and fixed a real, live-reproduced resource incident: the `ResourceWatchdog` (new in
beta.2) caught sustained 70–145% CPU of one core during a real session. The root cause was an
unthrottled `SendPointerEvent` per WPF mouse move (which can fire 100+ times per second), which
in the worst case forms a feedback loop with the remote compositor's own cursor drawing. Fixed by
throttling to ~60 Hz. A secondary contributing cause — a heap allocation per byte/pixel in the
ZRLE decoder — is also fixed. In addition, MyVNC now only allows one connection per host:port at
a time.

## Regression testing done for this release

- `dotnet build` (Debug + Release) and `dotnet test tests/MyVNC.Rfb.Tests` (42 tests, including
  full ZRLE coverage) green after every change, including the ZRLE allocation fix.
- **Live-verified**: reproduced the actual incident (RESOURCE WARNING in myvnc.log at 66–145%
  CPU), measured the update rate directly against the affected host (10–16 updates/s
  continuously) with a raw RFB probe, implemented the throttling, and confirmed via
  `Get-Process` thread sampling that total CPU load dropped after the fix (measured during the
  same live session, not just in theory).
- **Not fully verified**: exactly how much the ZRLE allocation fix contributed on its own compared
  with the pointer throttling — they landed in the same release and were tested together, not in
  isolation from each other.

## Risks

- The duplicate-connection guard is new and only manually tested against a handful of scenarios
  (same host, different host, tab mode). Not tested against window mode (a separate window per
  session) or race conditions from very rapidly repeated connection attempts.
