## Summary

A pure patch release for a single reported bug: after a failed connection it was not possible to
click "Connect" or the address dropdown on the card again — the buttons were greyed out, and only
re-enabled "after a while".

The root cause was that the card's active state was derived from the wrong question.
`IsSessionActive` was set from `FindActiveSession`, which matches *any open tab at all* on the
profile's host:port regardless of whether it is actually connected. A failed connection leaves
exactly such a tab behind: with automatic reconnect on, it sits there making three attempts with
backoff (2 s → 4 s → 8 s) before giving up and closing itself — hence "after a while" — and with
automatic reconnect off, it stays on the "Disconnected" overlay until the user closes it by hand,
so the button never wakes up at all. The card's state now comes from `HasConnectedSession`, which
requires `Framebuffer.IsConnected`.

`FindActiveSession` is deliberately unchanged. The duplicate guard must keep matching even a tab
that is only connecting or waiting in backoff, otherwise two clients could end up against the
same wayvnc server — exactly the resource conflict the guard exists for.

The other half of the bug was that the state was only recomputed when the dashboard gained focus.
A connection can fail while the dashboard already has focus, and then no activation comes along to
clear the stale state. `SessionWindow` now raises `SessionsChanged` when a tab is added, connects,
loses its connection or closes, and the dashboard recomputes on that signal.

Since the duplicate guard still blocks a second connection to a host whose tab is open but dead,
"Connect" on such a card now means "retry now": `RetryConnect` cancels any pending backoff and
starts an attempt immediately. The `SessionTab.IsConnecting` flag ensures that it cannot race an
attempt that is already in flight over the same framebuffer.

## Risks

- Small surface, but the guard against two simultaneous clients against the same server is
  touched. The guard in `MainWindow.OpenSession` is unchanged (`FindActiveSession` still matches
  every open tab); what has changed is only what the *card* shows and that a click can now trigger
  a retry in the existing tab. `RetryConnect` is a no-op for a connected tab and for a tab that
  already has an attempt in flight, so it cannot open a second connection.
- `RetryConnect` resets `ReconnectAttempt`, so a user-initiated retry restarts the backoff ladder.
  A host that is permanently down can therefore be kept in reconnect mode for as long as the user
  keeps clicking Connect, instead of the tab closing after three attempts. That is intentional —
  the click is an explicit "try again".
