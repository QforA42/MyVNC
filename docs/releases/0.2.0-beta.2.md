## Sammanfattning

Opt-in felsökningsloggning (`%APPDATA%\MyVNC\myvnc.log`, avstängd som standard) och en
resursvakt som varnar + alltid loggar om appen ser ut att gå amok med minne/CPU — direkt svar
på run-away-minnesincidenten som hittades och fixades under förra utvecklingscykeln. Även
README-förbättringar: installer-länk, sessionsskärmdumpar, tydligare Höger Ctrl-gest,
uppdaterad GitHub "About"-beskrivning.

## Regressionstestning som gjordes inför denna release

- `dotnet build` (Debug + Release) och `dotnet test tests/MyVNC.Rfb.Tests` (42 tester) gröna.
- **Liveverifierat**: aktiverade felsökningsloggning via UI-automation, anslöt till en riktig
  host (<hostname>), bekräftade att loggen fångar serverversion/säkerhetstyp/VeNCrypt-undertyp/
  upplösning utan några användaruppgifter. Bekräftade att "Öppna logg"-knappen korrekt
  aktiveras när loggfilen finns och öppnar den i Notepad.
- **Inte testat** (endast kodgranskat): `ResourceWatchdog`s faktiska varningsväg (ingen
  konstgjord minnes-/CPU-belastning framtvingad för att bekräfta att MessageBox faktiskt visas
  och `WriteAlways` loggar), att stänga av loggningsswitchen igen och bekräfta att loggning
  faktiskt upphör, loggfilens 5MB-trimning, samt de tre unhandled-exception-hakarna
  (`DispatcherUnhandledException`/`AppDomain.UnhandledException`/`TaskScheduler.UnobservedTaskException`)
  — ingen riktig exception har kastats för att bekräfta att de faktiskt fångar och loggar.

## Risker

- Se ovanstående otestade vägar — särskilt exception-hakarna och watchdog-varningen bör
  verifieras innan man litar på dem i ett verkligt krashscenario.
