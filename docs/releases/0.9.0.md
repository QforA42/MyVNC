**Commit range:** `v0.8.2..HEAD` (release-commit inkluderad)

**Included commits** (i git-ordning, `v0.8.2` exkluderad):

## Sammanfattning

Utlöstes av en läsbarhetsbugg som rapporterades efter ett byte av Windows-tema: rubriker,
sektionsetiketter och sidtitlar gick knappt att läsa. Grundorsaken var inte färgvalen i sig utan
en halvfärdig temahantering — appen läste visserligen Windows appläge vid start och valde
`Colors.Light.xaml`, men bakgrundsplattan (`TerminalCanvasBackground`), sessionsfönstrets
overlays och switchknopparna målades från hårdkodat mörka värden. Ljustemats mörka text hamnade
alltså på en nästan svart bakgrund. Alla färger kommer nu från temapaletten.

Samma genomgång visade att temat bara lästes vid uppstart. Temafärgerna konsumeras nu via
`DynamicResource` i stället för `StaticResource`, vilket gör att hela paletten kan bytas i drift:
ett byte av Windows appläge eller accentfärg målar om alla öppna fönster på plats — inklusive
sessionsfönster med aktiva RFB-anslutningar, som inte får rivas ner bara för att kromet ska
stylas om. `ThemeManager` lyssnar på två oberoende signaler: `SystemEvents` (WM_SETTINGCHANGE)
och en egen bevakare på registernycklarna, eftersom ett värde som skrivs av ett skript eller ett
temaverktyg ändrar temat utan att någon broadcastar det.

Accentfärgen hämtas nu från Windows (DWM:s `AccentColor`) i stället för appens egen fasta blå.
Eftersom accenten också används som text- och ikonfärg justeras den längs sin HSL-ljushet tills
den klarar 4,5:1 mot temats kortbakgrund, och text ovanpå en accentfylld yta växlar mellan vitt
och nästan svart. Logotypen behåller sin blå märkesfärg, som matchar aktivitetsfältsikonen.

Slutligen ett nytt val i Inställningar → TEMA: följ Windows (standard), ljust eller mörkt.
Accenten tas från Windows även när temat är låst — de två inställningarna är oberoende i Windows
självt också.

## Regressionstestning som gjordes inför denna release

- `dotnet build` (hela lösningen) grönt, `dotnet test` grönt (42/42).
- **Liveverifierat** mot den körande appen på Windows 11 i ljust systemtema:
  - Dashboard och Inställningar läsbara i ljust tema (buggen som utlöste releasen).
  - Byte av Windows appläge ljus → mörk → ljus under drift: hela UI:t målas om utan omstart.
  - Registerbevakaren fångar ett bytt appläge som skrivs utan WM_SETTINGCHANGE-broadcast.
  - Accenten (användarens teal `#459BAC`) slår igenom i knappar, ikoner och switchar, och
    mörknas till `#398090` i ljust tema för kontrastens skull.
  - Inställningen TEMA = Mörkt låser mörkt tema medan Windows står i ljust, och = Följ Windows
    återgår direkt. Valet sparas i `settings.json`.
- **Inte liveverifierat**: omtemning av ett sessionsfönster med en pågående RFB-anslutning.
  Kodstigen är densamma som för dashboarden (samma dynamiska resurser, samma palettbyte), men
  ingen live-session har temaväxlats under test.

## Risker

- Måttliga och breda snarare än djupa: `StaticResource` → `DynamicResource` berör 142
  referenser i all UI-XAML. Uppslagen sker nu vid rendering i stället för vid parsning, så ett
  felstavat eller borttaget resursnamn skulle visa sig som en osynlig/otemad kontroll i drift i
  stället för som ett fel vid start. Hela UI:t har gåtts igenom visuellt i båda teman.
- Accentfärgen är inte längre appens egen: en användare med en extrem accent i Windows får den
  färgen i MyVNC, om än kontrastjusterad. Den som vill ha tillbaka den fasta blå har inget val
  för det (bara ljust/mörkt/följ Windows).
