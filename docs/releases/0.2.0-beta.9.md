# 0.2.0-beta.9

**Date:** 2026-08-15

## Summary

beta.8's Wake button woke nothing. Dug further via SSH and found the real explanation: omarchy's
"screensaver" is not a special lock/DPMS layer — it is literally an ordinary terminal window
(alacritty/foot/kitty/ghostty) running `ttfx` (`/usr/share/omarchy/bin/omarchy-screensaver`). The
script closes itself with a simple `read -n1 -t 1` loop: it exits as soon as a single byte arrives
on the terminal's stdin.

A mouse click in a terminal sends nothing to the foreground process — which explains why clicks
never worked. Neither Shift nor F13 (both tested for real and confirmed sent via logging) worked
either, because most terminal emulators send no escape sequence at all for a lone modifier key or
an F13–F24 key — nothing ever reached `ttfx`'s stdin. Ctrl+Alt+Del only "worked" because Delete
happens to map to a real, widely recognized terminal escape sequence — not for any DPMS/idle
related reason, which was the original (wrong) theory in beta.8.

Switched the Wake button to send a space instead — guaranteed to produce a literal byte in every
terminal emulator, with no side effect worse than an extra space character if it lands somewhere
else. Live-verified: it now works.

Also took the opportunity to remove the ResourceWatchdog's MessageBox popup, since in practice it
turned out to trigger routinely during ordinary active session use (not just in genuine runaway
incidents) — more noise than signal. It is still always logged to myvnc.log.
