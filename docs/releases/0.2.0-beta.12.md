# 0.2.0-beta.12

**Date:** 2026-08-16

## Summary

Two things in this release.

**File transfer (send/receive), over SFTP.** The RFB/VNC protocol has no built-in file-transfer
capability, and wayvnc implements none of the extensions (TightVNC/UltraVNC) that usually add it
— so file transfer was built as a separate side-channel over SFTP (SSH, port 22), not part of the
VNC connection. "Send file…" (button or drag-and-drop onto the session) uploads to a fixed
`~/myvnc-shared` folder on the remote machine; "Receive file…" lists what is there and downloads
the selected files to a local folder. It reuses the same username/password already stored for the
VNC connection — this works automatically when wayvnc is configured with `enable_pam=true`, since
that is then the same as the host's Linux login.

**Documented: the SSH button also covers initramfs unlock on reboot.** A real live reboot of
<hostname> was used as the test: the host rebooted, wayvnc/the desktop was of course not up, but
dropbear-initramfs (listening on the same port 22) was. SSHed in with a one-off identity file, ran
the unlock command manually, and confirmed that MyVNC's auto-reconnect picked the session up
automatically just as wayvnc came up afterward — 8 reconnect attempts with clean exponential
backoff, then a successful connection. No code change was needed; it already worked. Only
documented in the README.
