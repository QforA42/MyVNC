# 0.2.0-beta.14

**Date:** 2026-08-17

## Summary

Reported live: the app "hung" again. The log showed a tab still trying to reconnect to a dead
address (wrong port, nothing listening there) after 55+ attempts and well over an hour — and,
still unexplained, a SECOND, independent reconnect sequence for the same tab running in parallel
(two different attempt counters climbing simultaneously in the log, confirmed via `grep` on
"attempt 1)" lines at three different points in time without the connection ever actually
succeeding). The root cause of the double loop has not been found yet, but whatever the cause, it
was clearly wrong to let reconnecting continue forever against a target that will never answer.

Fixed pragmatically: give up and close the tab automatically after 3 failed reconnect attempts,
instead of continuing indefinitely. This limits the damage regardless of what is actually causing
the double loop.

## Risks

The root cause of the observed double reconnect loop is not established — if it recurs it should
now at least be self-limiting (tabs close after 3 attempts instead of running forever), but the
underlying "why two loops" is still unknown.
