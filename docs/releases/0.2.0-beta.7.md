# 0.2.0-beta.7

**Date:** 2026-08-15

## Summary

The same class of bug as the click fix in beta.6, discovered right afterward: the mouse wheel did
nothing in a session. `RemoteFramebufferControl` subscribed to the bubbling `MouseWheel` event,
but `ScrollHost` (the `ScrollViewer` wrapping the framebuffer image) consumes `MouseWheel` for its
own scrolling and marks it handled before it ever bubbles up to the control.

Switched to `PreviewMouseWheel` (tunneling), the same pattern as the mouse-button fix. The event
is also marked handled afterward so that the local view does not scroll twice in "actual size"
mode (where `ScrollHost` actually has something to scroll).

Live-verified directly by the user against a real session.
